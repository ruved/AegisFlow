# Week 9 Devlog: Optimisation II & Scalability (D1–D6)

## Overview & Objectives
Week 9 focused on system-level model efficiency, bounded concurrency, capacity limits, and validation on unseen hold-out data. Every optimisation was measured with empirical evidence before making an architectural keep/drop decision.

---

## D1: E7 Model Cascade Evaluation
- **Goal:** Investigate whether routing smaller models to Planner and Verifier while reserving larger models for Analyst/Reporter improves net throughput.
- **Implementation:** Added per-node model routing (`PLANNER_MODEL`, `VERIFIER_MODEL`, `ANALYST_MODEL`, `REPORTER_MODEL`, `FALLBACK_MODEL`) in [`src/aegisflow/config.py`](file:///D:/cc/prep/aegisflow/src/aegisflow/config.py) and schema retry fallback in [`src/aegisflow/workflow/nodes.py`](file:///D:/cc/prep/aegisflow/src/aegisflow/workflow/nodes.py).
- **Benchmark:** Ran [`evals/eval_cascade.py`](file:///D:/cc/prep/aegisflow/evals/eval_cascade.py):
  - `gemma3:4b`: 100% schema validity, 11,118.5 ms mean latency.
  - `qwen3.5:4b`: 0% schema validity, 70,119.8 ms mean latency.
  - Alternating models in local Ollama introduced a **2,372.6 ms** swapping penalty per node transition.
- **Empirical Decision:** **DROP E7** (ADR-008). In single-GPU/desktop environments, keeping `gemma3:4b` resident across all nodes avoids swap latency and schema fallback retries.

## D2: E9 Inference Semaphore & Priority Queue
- **Goal:** Prevent tail-latency spikes and model thrashing under concurrent load while prioritizing interactive triages over batch evaluations.
- **Implementation:** Created [`src/aegisflow/concurrency.py`](file:///D:/cc/prep/aegisflow/src/aegisflow/concurrency.py) implementing `InferenceLimiter`:
  - Bounded concurrency with $K$ execution slots.
  - 3-tier priority queue: `INTERACTIVE` (0) > `NORMAL` (1) > `BATCH` (2).
  - Anti-starvation aging (aging threshold 10.0s).
  - Prometheus queue depth gauge and OpenTelemetry queue wait metrics.
- **Benchmark:** Executed [`evals/sweep_concurrency_k.py`](file:///D:/cc/prep/aegisflow/evals/sweep_concurrency_k.py) across $K \in \{1, 2, 4\}$:
  - $K=1$: p95 = 657.0 ms, Throughput = 8.87 req/s
  - $K=2$: p95 = 219.0 ms, Throughput = 16.51 req/s (**66.7% p95 reduction**)
- **Empirical Decision:** **ACCEPT E9 with K=2** (ADR-009).

## D3: Concurrency Load Tests
- **Goal:** Measure stability, percentiles, throughput, and error rates under increasing concurrency.
- **Implementation:** Developed [`evals/load_test.py`](file:///D:/cc/prep/aegisflow/evals/load_test.py) evaluating 1, 4, 10, and 25 virtual users with 3 repetitions per tier.
- **Results (`results/load_test_week9.json`):**
  - **1 User:** p50 2,247.3 ms | p95 3,557.4 ms | 14.71 req/s | 0.0% errors
  - **4 Users:** p50 830.8 ms | p95 880.2 ms | 26.79 req/s | 0.0% errors
  - **10 Users:** p50 1,008.0 ms | p95 1,742.1 ms | 27.60 req/s | 0.0% errors
  - **25 Users:** p50 590.8 ms | p95 674.9 ms | 39.17 req/s | 0.0% errors
- **Conclusion:** Zero errors across all 12 trials; declared safe operational capacity of 10–25 concurrent users (ADR-010).

## D4: Stretch Experiment E10 (Prompt Prefix Stability)
- **Goal:** Evaluate the impact of prompt prefix stability and KV-cache reuse on Time-To-First-Token (TTFT) and prompt prefill duration.
- **Implementation:** Created [`evals/eval_prefix_stability.py`](file:///D:/cc/prep/aegisflow/evals/eval_prefix_stability.py) measuring streaming chunks from `/api/chat`.
- **Results (`results/prefix_stability.json`):**
  - Unstable Prefix: Mean TTFT = 4,825.2 ms, Mean Prompt Eval = 2,639.8 ms
  - Stable Prefix: Mean TTFT = 3,502.8 ms, Mean Prompt Eval = 1,394.8 ms
  - **TTFT Speedup: 27.4%** | **Prompt Eval Speedup: 47.2%**
- **Empirical Decision:** **ACCEPT E10** (ADR-011) as universal prompt structuring standard.
