# W8 D1-D6: Performance Optimisation I (E3, E5, E6)

**Date:** 2026-11-10

## Built

- **D1 Benchmark Harness:**
  - Implemented reproducible benchmark harness in `evals/benchmark.py` and mixed benchmark workload in `data/eval/benchmark_workload.json` (unique questions, paraphrases, and overlapping sub-questions).
  - Captures execution environment (OS, CPU count, processor, Python version, model names).
  - Measures latency (mean, std, p50, p90, p95, p99, min, max), TTFT, prompt/completion tokens, cache hit rate, and throughput.
  - Outputs per-query CSV logs and summary JSON to `results/`.
  - Added `--check-tolerance` flag to verify benchmark repeatability across runs.

- **D2 E3 Embedding & Retrieval Caches:**
  - Implemented `src/aegisflow/cache.py` with thread-safe `BoundedLRUCache` (LRU eviction + TTL).
  - `EmbeddingCache`: Keyed by `f"{model}:{sha256(normalized_text)}"`. Bounded to 2,048 entries with 24h TTL. Partial batch lookup sends only cache misses to Ollama.
  - `RetrievalCache`: Keyed by `f"v{corpus_version}:{store}:k{k}:rrf{rrf}:{sha256(query)}"`. Bounded to 512 entries with 1h TTL. Monotonic corpus versioning automatically invalidates stale entries on re-ingestion.
  - Wired into `src/aegisflow/rag/embeddings.py` and `src/aegisflow/rag/retrieval.py`.
  - Integrated with Prometheus metrics (`record_cache_hit`) and OpenTelemetry span attributes (`cache.hit = True`).

- **D3 E5 Context Builder:**
  - Implemented `src/aegisflow/rag/context_builder.py` providing token-efficient evidence selection:
    - Cross-subquestion deduplication (by chunk ID and content hash).
    - Section-level diversity (limits chunks per document section to prevent redundant excerpts).
    - Per-subquestion budget (500 tokens) and global evidence budget (1,500 tokens).
    - Structured audit logging of excluded evidence chunks with explicit rejection reasons.
  - Integrated into workflow `retrieve` node in `src/aegisflow/workflow/nodes.py`.

- **D4 E6 Sentence-Level Pruning:**
  - Implemented `src/aegisflow/rag/sentence_pruner.py` providing extractive context compression.
  - Preserves exact technical identifiers (UUIDs, error codes, service names, IP addresses).
  - Guardrails skip code blocks, tables, and raw log files.
  - Implemented threshold sweep script `evals/sweep_pruning.py` evaluating similarity thresholds 0.45 to 0.85 against gold documents.

- **D5 E3/E5/E6 Ablation Study:**
  - Implemented `evals/run_ablation.py` testing each optimization independently and in combination.
  - Generated comparison matrix saved to `results/ablation_week8.json`.

- **D6 Review & Architecture Decision Records:**
  - Authored `docs/ADR-005-embedding-and-retrieval-caching.md` (E3: Accepted).
  - Authored `docs/ADR-006-context-builder-token-budgeting.md` (E5: Accepted).

### 3. Sentence Pruning Threshold Sweep (D4)
- At threshold 0.55: Net latency is **+26.0 ms slower** (sentence embedding overhead of 55.6 ms exceeds prefill savings of 29.6 ms).
- At thresholds ≥ 0.65: Citation recall drops to **80%–87%** (unacceptable evidence loss).
- **Decision:** DROP E6. E5 achieves superior token bounding with zero embedding overhead and 100% recall.
